1. 개요

fido-admin.sh 는 FIDO Admin 실행 jar 를 백그라운드로 띄우고, 상태를 확인하고, 안전하게 내리는 스크립트다. 프로파일(prod, qa, local 또는 임의의 이름)을 명령 인자로 골라 띄울 수 있다.

기능설명
어떤 프로파일로도 기동start qa, start prod, start qa,debug 처럼 인자로 지정한다.
프로파일별 설정 파일fido-admin-<프로파일>.env 와 공통 fido-admin.env 를 읽는다.
기동 전 점검DB 접속 정보가 없거나 프로파일 이름이 잘못되면 띄우지 않는다.
중복 기동 방지이미 실행 중이면 새로 띄우지 않는다.
안전한 종료정상 종료 신호 후 감사 로그 대기열을 비울 시간을 기다린다.

2. 사전 준비

  • Java 17 이상. PATH 의 java 를 쓰며, 다른 JDK 를 쓰려면 JAVA_HOME 을 지정한다.
  • bash (Linux 기본 셸이면 충분하다). jar 안의 프로파일 확인에 unzip 이 있으면 쓰고, 없으면 그 확인만 건너뛴다.
  • 실행 jar. 빌드 서버나 개발 PC 에서 만든다.
./gradlew bootJar
# 결과: build/libs/fido-admin-0.1.0-SNAPSHOT.jar  (-plain.jar 는 실행용이 아니다)
  • DB 접속 정보. local 외 프로파일은 URL·계정·비밀번호 세 값이 반드시 있어야 한다.

3. 서버 배치

스크립트는 자기 위치의 한 단계 위를 앱 디렉터리로 본다. 다음처럼 배치하는 것을 권장한다.

/opt/fido-admin/                       ← 앱 디렉터리
├── fido-admin-0.1.0-SNAPSHOT.jar      ← 실행 jar (가장 최근 파일을 자동 선택)
├── fido-admin.pid                     ← 실행 중일 때 생성 (PID)
├── fido-admin.pid.profile             ← 실행 중인 프로파일
├── logs/                              ← 기본 로그 디렉터리
└── scripts/
    ├── fido-admin.sh
    ├── fido-admin.env.example         ← 설정 예시 (복사해서 쓴다)
    ├── fido-admin.env                 ← 공통 설정 (직접 만듦)
    ├── fido-admin-qa.env              ← qa 전용 설정 (직접 만듦)
    └── fido-admin-prod.env            ← prod 전용 설정 (직접 만듦)
chmod +x /opt/fido-admin/scripts/fido-admin.sh
chmod 600 /opt/fido-admin/scripts/fido-admin*.env   # 비밀번호가 들어가므로 소유자만 읽게 한다

jar 를 다른 곳에 두려면 APP_JAR 로 경로를 지정한다. 지정하지 않으면 앱 디렉터리, 그다음 build/libs 에서 가장 최근 fido-admin*.jar 를 찾는다.

4. 설정 파일

설정은 KEY=VALUE 형식의 텍스트 파일이다. # 으로 시작하는 줄은 주석이고, 값의 바깥 따옴표는 벗겨진다. 기본 위치는 scripts/ 이며 FIDO_ADMIN_ENV_DIR 로 바꿀 수 있다.

파일용도
fido-admin-<프로파일>.env그 프로파일에서만 쓰는 값. 예: qa DB 와 prod DB 를 나눠 적는다.
fido-admin.env모든 프로파일 공통 값. 기본 프로파일(SPRING_PROFILES_ACTIVE)도 여기 적을 수 있다.
1순위서버 환경 변수
›
2순위fido-admin-<프로파일>.env
›
3순위fido-admin.env

같은 키가 여러 곳에 있으면 위 순서로 앞의 것이 이긴다. 여러 프로파일(qa,debug)이면 적은 순서대로 각 프로파일 파일을 읽는다.

설정 항목

키필수설명
SPRING_DATASOURCE_URLlocal 외 필수JDBC URL. 예: jdbc:oracle:thin:@db-host:1521/SERVICE
SPRING_DATASOURCE_USERNAMElocal 외 필수DB 계정
SPRING_DATASOURCE_PASSWORDlocal 외 필수DB 비밀번호. 평문 대신 ENC(...) 암호문 가능
DB_CONFIG_KEY암호문 사용 시암호문 복호화 키(Base64, 32바이트)
FIDO_ADMIN_EXTERNAL_ALLOWED_CIDRS선택인증 없는 서버 간 경로의 접근 허용 대역. 쉼표 구분. 비우면 모두 허용
SPRING_PROFILES_ACTIVE선택인자 없이 띄울 때의 기본 프로파일(공통 파일에서만 의미 있음)
APP_JAR선택실행할 jar 경로
LOG_PATH선택로그 디렉터리. 기본 <앱 디렉터리>/logs
JAVA_HOME선택사용할 JDK 경로
JAVA_OPTS선택JVM 옵션. 기본 -Xms512m -Xmx1g
STOP_TIMEOUT선택종료 대기 초. 기본 60 (30 미만 비권장)

작성 예

# scripts/fido-admin-qa.env
SPRING_DATASOURCE_URL=jdbc:oracle:thin:@qa-db:1521/FIDOQA
SPRING_DATASOURCE_USERNAME=fidoadmin
SPRING_DATASOURCE_PASSWORD='ENC(...)'
LOG_PATH=/var/log/fido-admin-qa

# scripts/fido-admin.env (공통)
DB_CONFIG_KEY=Base64로_된_32바이트_키
FIDO_ADMIN_EXTERNAL_ALLOWED_CIDRS=10.0.0.0/8
JAVA_OPTS=-Xms512m -Xmx1g
DB 비밀번호 암호화 키를 만들고 비밀번호를 암호문으로 바꾼 뒤, 암호문을 SPRING_DATASOURCE_PASSWORD 에, 키를 DB_CONFIG_KEY 에 적는다. 
export DB_CONFIG_KEY=$(openssl rand -base64 32)     # 키는 안전한 곳에 따로 보관
DB_CONFIG_VALUE='비밀번호' ./gradlew -q encryptDbConfig   # → ENC(...) 출력

5. 명령

명령동작
start [프로파일]지정한 프로파일로 띄운다. 이미 실행 중이면 아무것도 하지 않는다.
stop실행 중인 프로세스를 정상 종료한다.
restart [프로파일]내렸다가 다시 띄운다. 프로파일을 빼면 실행 중이던 프로파일 그대로 띄운다.
status실행 여부, PID, 실행 프로파일을 보여 준다.
scripts/fido-admin.sh start prod          # 운영
scripts/fido-admin.sh start qa            # QA
scripts/fido-admin.sh start local         # 로컬 도커 DB (개발 PC)
scripts/fido-admin.sh start qa,debug      # 여러 프로파일을 함께 (쉼표로 구분)
scripts/fido-admin.sh restart             # 실행 중인 프로파일 그대로 재기동
scripts/fido-admin.sh restart prod        # 다른 프로파일로 바꿔 재기동
scripts/fido-admin.sh status
scripts/fido-admin.sh stop

정상 출력 예

$ scripts/fido-admin.sh start qa
시작: /opt/fido-admin/fido-admin-0.1.0-SNAPSHOT.jar (profile=qa)
실행 중 (PID 51103, profile=qa). 콘솔 출력: /var/log/fido-admin-qa/console.out

$ scripts/fido-admin.sh status
실행 중 (PID 51103, profile=qa)

$ scripts/fido-admin.sh stop
종료 중 (PID 51103, profile=qa) ...
종료했습니다.
"실행 중" 은 프로세스가 살아 있다는 뜻이다 스크립트는 기동 3초 뒤 프로세스 생존만 확인한다. 화면이 실제로 열리는지는 잠시 뒤 curl -I http://localhost:8080/login 으로 확인한다(200 응답이면 정상).

기본prod
  • 이름은 영문·숫자·_·- 만 쓸 수 있고, 여러 개는 쉼표로 잇는다(공백 없이). 그 밖의 문자는 거부한다.
  • jar 에 들어 있는 프로파일 설정은 local, qa, prod 다. 그 밖의 이름(예: staging)도 띄울 수 있지만, 해당 설정 파일이 없다는 안내가 나오고 공통 설정과 환경 변수만으로 동작한다.
  • local 이 들어 있으면 DB 접속 정보 점검을 건너뛴다(로컬 도커 DB 가 설정에 고정돼 있다).

7. 로그 · PID · 종료

로그

파일 (LOG_PATH 아래)내용
fido-admin.log애플리케이션 전체 로그. 일자별 롤링, 30일 보관
fido-admin-error.logWARN 이상만
console.out표준 출력·오류. 기동 실패 원인은 대부분 여기에 남는다

모든 로그 줄에 [req=요청ID user=로그인ID tenant=소속] 이 붙고, 같은 요청 ID 가 응답 헤더 X-Request-Id 로 나간다. 오류 신고 때 이 값을 받으면 해당 요청의 로그만 찾을 수 있다.

PID 파일

fido-admin.pid(PID)와 fido-admin.pid.profile(실행 프로파일)을 앱 디렉터리에 만든다. 위치는 PID_FILE 로 바꿀 수 있다. 프로세스가 이미 없는데 파일이 남아 있으면 다음 명령 때 스스로 지운다.

종료 절차

  1. 정상 종료 신호(SIGTERM)를 보낸다.
  2. 애플리케이션은 처리 중인 요청을 마치고, 감사 로그 대기열을 최대 30초까지 비운 뒤 끝난다.
  3. STOP_TIMEOUT(기본 60초)이 지나도 남아 있으면 강제 종료(SIGKILL)한다.
주의 kill -9 로 직접 죽이거나 STOP_TIMEOUT 을 30초보다 짧게 잡으면, 대기열에 남은 감사 로그가 유실될 수 있다. 항상 stop 또는 restart 명령으로 내린다.

8. 종료 코드

코드의미
0성공. 이미 실행 중인데 start 하거나, 실행 중이 아닌데 stop 한 경우도 0 이다.
1기동 실패: jar 없음, DB 접속 정보 없음, 기동 직후 프로세스 종료
2사용법 오류: 알 수 없는 명령, 잘못된 프로파일 이름
3status 결과 실행 중이 아님

배포 자동화나 모니터링 스크립트에서 이 코드로 성공 여부를 판단할 수 있다.

9. 운영 예시

처음 설치

mkdir -p /opt/fido-admin/scripts
cp fido-admin-0.1.0-SNAPSHOT.jar /opt/fido-admin/
cp scripts/fido-admin.sh scripts/fido-admin.env.example /opt/fido-admin/scripts/
cd /opt/fido-admin/scripts
cp fido-admin.env.example fido-admin-prod.env   # 값 채우기
chmod +x fido-admin.sh && chmod 600 fido-admin*.env
./fido-admin.sh start prod

새 버전 배포

cp fido-admin-<새 버전>.jar /opt/fido-admin/   # 가장 최근 jar 가 자동 선택된다
/opt/fido-admin/scripts/fido-admin.sh restart     # 같은 프로파일로 재기동
curl -I http://localhost:8080/login                # 200 확인

이전 jar 는 되돌릴 때를 위해 잠시 남겨 두고, 되돌릴 때는 새 jar 를 치우거나 APP_JAR 로 이전 jar 를 지정해 restart 한다.

프로파일 바꾸기 (예: QA 서버를 운영과 같은 설정으로 띄워 보기)

scripts/fido-admin.sh restart prod      # fido-admin-prod.env 의 값으로 재기동
scripts/fido-admin.sh status            # 실행 중 (PID …, profile=prod)
scripts/fido-admin.sh restart qa        # 원래대로

운영 DB 를 가리키는 fido-admin-prod.env 가 QA 서버에 있으면 QA 서버가 운영 DB 에 붙는다. 서버마다 그 서버에서 쓸 프로파일 파일만 둔다.

서버 재부팅 후 자동 기동 (선택)

# crontab -e (서비스 계정)
@reboot /opt/fido-admin/scripts/fido-admin.sh start prod

10. 문제 해결

증상·메시지조치
실행할 jar 를 찾지 못했습니다앱 디렉터리나 build/libs 에 jar 를 두거나 APP_JAR 를 지정한다.
환경 변수가 없습니다: SPRING_DATASOURCE_…안내된 fido-admin-<프로파일>.env 나 fido-admin.env 에 DB 접속 정보를 적는다.
프로파일 이름이 올바르지 않습니다영문·숫자·_·- 만, 여러 개는 공백 없이 쉼표로 잇는다.
참고: jar 에 application-<이름>.yml 이 없습니다오타가 아닌지 확인한다. 의도한 이름이면 무시해도 된다.
기동에 실패했습니다함께 출력되는 console.out 마지막 30줄을 본다. DB 접속 실패, 8080 포트 사용 중, 암호문 키 불일치가 흔한 원인이다.
"실행 중" 인데 화면이 안 열린다기동에 수십 초 걸릴 수 있다. fido-admin.log 에서 Started 줄과 오류를 확인한다.
이미 실행 중입니다restart 를 쓰거나 stop 후 start 한다.
60초 안에 끝나지 않아 강제 종료합니다오래 걸리는 요청이 있었는지 로그를 확인한다. 반복되면 STOP_TIMEOUT 을 늘린다.
